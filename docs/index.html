Bring your Mac to life.

Not another general-purpose engine

llama.cpp, mlx-lm and oMLX run thousands of models with one shared set of machinery. That breadth is their strength, and it leaves memory and speed unused for any one model on a small machine. Nuemac gives each supported model its own cache layout, kernels and weight trims, designed from its architecture and measured on the Mac it targets. For Inkling 2 Mini, Thinking Machines' 26.4B-parameter looped mixture of experts, that took a day from release.

Built around the model's shape

Inkling makes 48 attention passes per token, and 40 only ever look back 1,024 tokens. Nuemac keeps full history for the 8 that read it, at 8 bits, and reads it with a Metal kernel written for this exact layout: 20 ms per token at 96K, against 73 ms with plain MLX ops.

Measured down to the byte

A whole-token profile showed the expert kernels already near the chip's bandwidth. So the last gain came from reading less: bf16 loop controllers instead of fp32 copies, and a 6-bit output head checked at KL 0.0003. +5% decode, same answers.

Every number can be checked

A quality gate before any speed claim. Token-for-token checks against the reference, and an alternating A/B for every engine change: one kernel that won in isolation lost on short prompts, so it now only switches on above 12K tokens. Raw results and the failed experiments are published.

Private by construction

The server listens on 127.0.0.1 only and holds no outside connections while serving. Weights are downloaded once at install. No account, no telemetry, no per-token bill. The Mac on your desk becomes the AI.

Several users at once

Since 0.5.0, up to 4 requests run together. They join and leave one decode batch between steps, and a long prompt is read in chunks that take turns with the replies already streaming. One request alone is exactly as fast as before and gives the same text.

One request alone also drafts from its context (0.6.0): when a reply repeats something already in the conversation, such as a file being rewritten or edited, the next tokens are read off the earlier copy and checked up to 16 at a time. A 240-line file rewrite on the M4 Pro goes from 40.8 to 66-72 tok/s; prose is unchanged. Details: recipe.

Why 4 requests give ~1.4× and not 4×: each one picks its own 8 of 128 experts per layer pass, so 4 together read ~3.7× the expert weights of one. Attention is only ~14% of a step; batching it into one kernel launch (adapted from mlx-serve, MIT) cut the step 4.5%. Rows in a batch round slightly differently than alone, so greedy text can drift from a solo run, as in other batching servers. Raw numbers: results/.

What the installer does

Each step is in a short shell script you can read before you run it.

01

Checks your Mac

Apple Silicon, macOS 14+, 16 GB, enough disk. --dry-run stops here and prints the plan.

02

Fetches pinned builds

oMLX from Homebrew, Nuemac from GitHub, and the model from Hugging Face at a fixed revision. Every file is checked against its SHA-256, and downloads resume if they drop.

03

Makes room on the GPU

macOS lets the GPU use ~10.7 GB of 16 by default. With your OK it raises that to 14.5 GB, and can keep it after reboot.

04

Starts a local server

An OpenAI-compatible API on 127.0.0.1:8080, started at login and restarted if it crashes. Loopback only.

05

Checks the answers

Twelve known-answer questions before you trust any speed number. A fast model that outputs garbage is the most common failure.

06

Gives you nuemac

status, models, bench, use, logs. New models arrive as families with their own recipes.

Four things we learned on Inkling

The full log, with every experiment and its control, is in the Inkling recipe.

48 caches where 8 will do

Inkling makes 48 layer passes per token, and 40 of them only look back 1,024 tokens. oMLX kept a full-length cache on all 48 (~192 KB per token), so it fit only ~7K tokens. Window caches on those 40 passes give the same output.

An 8-bit cache needs its own kernel

The 8 global passes store 8-bit keys and values (1.6 GB at 96K). Plain MLX ops read them at ~23 GB/s. A split-K Metal kernel reads them at ~84 GB/s: 20 ms per token at 96K instead of 73.

Near the floor, cut bytes

A token reads 3.35 GB of weights, and MLX's expert matvecs already run at 79-87 GB/s. So the last gain came from bytes: bf16 instead of fp32 loop controllers, and a 6-bit output head (KL 0.0003). +5% decode.

The drafter works, and doesn't help

Inkling's own DSpark draft head is accepted 56-76% of the time on MLX. Checking two tokens still costs ~1.8× one step, because they route to nearly twice the experts. On a base M4 it's a wash.

Use it

Any OpenAI-compatible client works. Point it at the local endpoint.

# chat with it
curl http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "inkling-2-mini",
  "messages": [{"role": "user", "content": "Explain mixture-of-experts in two sentences."}]
}'

# measure your own Mac, then try the other model
nuemac bench
nuemac bench --depth 32768        # adds a needle at 32K
nuemac models                     # supported models
